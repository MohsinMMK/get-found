# The get-found checklist — what "done" means for each item

Facts here were verified against official docs on 2026-11-02. If `.get-found/rules-notes.md` says something newer, that wins. Each item lists **why**, **pass when**, **verify**, **fix**, and **keep it fresh**. The id is what `state.py` and the ledger use.

## Contents
1. Index — `search-console` · `bing-webmaster` · `indexnow` · `sitemap` · `crawlability`

## 1. Index

### search-console
- **Why**: the only first-party view of how Google crawls, indexes and shows the site, and where you submit sitemaps and control AI-feature inclusion.
- **Pass when**: a **Domain property** (`sc-domain:example.com`, DNS TXT verification — covers http/https, www and subdomains) is verified; sitemap submitted and status "Success"; Settings → *Search generative AI* is **Include** (default) unless the owner chose to exclude; no unexplained spike in "Not indexed" reasons.
- **Verify**: `submit.py google sitemaps` (needs credentials) or ask the user for a screenshot of Sitemaps + Pages reports. The audit looks up the `google-site-verification` DNS TXT record (and the meta tag); when it finds a token, ingest moves the item from `todo` to `manual` — a token proves setup was started, not that the property is verified, so confirm with the owner. Record evidence with `state.py mark search-console --status pass --evidence "..."`.
- **Fix**: walk the user through references/google.md §Setup. Agent cannot click through Google's UI or edit DNS — give exact values and wait.
- **Keep fresh**: monthly look at Pages (indexing) report and Performance; after domain/hosting/framework changes re-check verification.

### bing-webmaster
- **Why**: Bing's index grounds Microsoft Copilot, and Bing results feed DuckDuckGo, Yahoo and others; its AI Performance report is the only first-party AI-citation data.
- **Pass when**: site verified (fastest: *Import from Google Search Console*), sitemap submitted, API key generated if automation is wanted (stored as `BING_WEBMASTER_API_KEY`, never in a file).
- **Verify**: `submit.py bing sites` / `bing sitemaps`.
- **Fix**: references/bing-indexnow.md.
- **Keep fresh**: monthly AI Performance + Search Performance check (measurement mode).

### indexnow
- **Why**: one ping notifies Bing, Yandex, Naver, Seznam, Yep (and Amazon) of new/changed/deleted URLs within minutes. Microsoft recommends it as the primary real-time method. Google does not participate (it uses sitemaps).
- **Pass when**: key file `/{key}.txt` is live and matches config; every new, changed **and removed** URL is submitted after each deploy (`state.py changes --channel indexnow` is empty).
- **Verify**: audit checks the key file; `state.py changes`.
- **Fix**: `submit.py indexnow-key` (public dir from `init --app-dir`, or `--public-dir <static dir>`) → deploy → `submit.py indexnow --from-state --dry-run` → `submit.py indexnow --from-state`. URLs go per host: apex and www each need the key file served on that host. Don't resubmit the same URL within ~10 minutes; don't ping unchanged URLs.
- **Keep fresh**: every sync. On hosted platforms with a built-in IndexNow integration (some CMS/CDNs offer it), enable that instead and mark the item pass with evidence.

### sitemap
- **Why**: the main discovery and recrawl hint for Google and Bing.
- **Pass when**: generated by the framework/CMS (plain static sites: a small script or a carefully maintained file — see frameworks.md); contains every canonical, indexable, 200-status URL and nothing else (no noindex, redirects, 404s, staging hosts, parameter duplicates); `<lastmod>` reflects real content changes (Google uses it only if "consistently and verifiably accurate"; `priority`/`changefreq` are ignored); ≤ 50,000 URLs / 50 MB per file (index above that); listed in robots.txt as an absolute `Sitemap:` URL; submitted to Google and Bing.
- **Verify**: audit (`sitemap-*` codes, `missing-from-sitemap`, `lastmod-datemodified-mismatch` when `<lastmod>` and the page's JSON-LD `dateModified` disagree, `sitemap-disallowed` for URLs robots.txt blocks).
- **Fix**: references/frameworks.md. Common bug: every lastmod = build time → derive from content dates or git commit dates of the source file.
- **Keep fresh**: re-audit on every sync; resubmit only when the sitemap URL changes (engines refetch it on their own; the old Google "ping" endpoint is dead).

### crawlability
- **Why**: if crawlers can't fetch or are told not to index, nothing else matters.
- **Pass when**: robots.txt returns 200 text (4xx = allow all, 5xx = engines assume disallow all), < 500 KiB, doesn't block CSS/JS or important paths; one canonical origin (https + chosen www/non-www, others 301); self-referencing absolute canonicals on indexable pages; no accidental `noindex` (meta or `X-Robots-Tag`) on pages meant to rank; unknown URLs return real 404 (no soft-404s); viewport meta; HTML < 2 MB (Googlebot reads the first 2 MB).
- **Verify**: audit. The crawler obeys robots.txt for Googlebot; disallowed-but-linked URLs show as `robots-disallowed-linked` (info). The redirect chains for `http://`, `http://www` and `https://www` are checked separately (`http-not-redirected`, `www-duplicate`, `redirect-temporary`, `redirect-chain`). Product/shop pages that are noindex on purpose: record them in `config.json` `intentional_noindex` (`[{"path": "/products/", "reason": "pre-launch"}]`) so `commercial-pages-noindex` becomes info.
- **Fix**: framework config / hosting redirects. Staging must be noindexed or password-protected.
- **Keep fresh**: on deploy-config changes, new hosting/CDN, framework upgrades.

## 2. Present

### titles  ("a real title")
- **Why**: the title link is the first thing a searcher reads; generic titles ("Home", "Vite + React") make pages indistinguishable and AI engines use titles to understand pages too.
- **Pass when**: every indexable page has a unique `<title>` that says what the page is (leading with its primary keyword in natural words), then a separator and the brand; matches the visible `<h1>` in meaning; unique meta description that summarises the page's value (Google has no length limit — it truncates by pixel width; ~50–60 char titles and ~150–160 char descriptions are display heuristics, not rules); favicon on the homepage as PNG/ICO ≥ 48×48 (SVG alone isn't in Google's supported list).
- **Verify**: audit (`title-*`, `description-*`, `duplicate-*`, `favicon-*`) + `state.py keywords --check` (keyword reflected in title).
- **Fix**: framework title template (`%s | Brand`) + per-page metadata. Write titles for humans; no keyword stuffing; no ALL CAPS.
- **Keep fresh**: every new/changed page; monthly review of pages with high impressions but low CTR in Search Console (rewrite title/description).

### preview-images  ("preview image")
- **Why**: link previews on WhatsApp, LinkedIn, X, Facebook, Slack, Discord, iMessage and in Google (og:image is a thumbnail candidate) decide whether people click shares.
- **Pass when**: every indexable page has `og:title`, `og:description`, `og:url` (canonical), `og:type`, `og:image` (absolute https, ~1200×630, ≈1.91:1, **< 600 KB** for WhatsApp — aim < 300 KB), `og:image:width/height/alt`, `og:site_name`, `twitter:card=summary_large_image`; `<head>` closes within the first 300 KB of HTML (WhatsApp); preview fetchers (facebookexternalhit, Twitterbot, LinkedInBot…) not blocked in robots.txt.
- **Format**: JPEG or PNG is safest; WebP/AVIF og:images render on most platforms but not all (audit: `og-image-webp`, info). Pages that are noindex still get link previews when shared, so their OG tags are checked too (at info level). `og:url` must be the page's own canonical, not the homepage (`og-url-homepage`).
- **Verify**: audit; then the platform debuggers (references/previews-social.md).
- **Fix**: framework OG image generation per page (blog posts get their own), or `scripts/og_image.py`. Keep key text centred (some apps crop to square).
- **Keep fresh**: new pages; brand changes; after changing an image, **change its URL** (platforms cache by URL) and re-scrape.

### structured-data
- **Why**: JSON-LD tells search and AI systems what the entity is (brand, logo, social profiles, author, dates, product, location). Not required for AI features, but it powers rich results and disambiguation.
- **Pass when**: homepage has `Organization` (or `LocalBusiness`/`Person`) with `name`, `url`, `logo` (≥ 112×112, crawlable) and `sameAs`, plus `WebSite` (`name`, `url`) for the site name; posts have `Article`/`BlogPosting` with `headline`, `author`, `datePublished`, `dateModified` matching visible dates; type-specific markup only where the page truly is that thing (Product with offers, SoftwareApplication, Event, JobPosting, Recipe, Review snippet, LocalBusiness…). Validates in Google's Rich Results Test / Schema Markup Validator.
- **Current eligibility (2026-11)**: FAQ rich results ended May 2026; HowTo ended 2023; several others retired 2025. Unused markup is harmless, but don't add FAQ/HowTo *for rich results*. Check the gallery source (`google-sd-gallery`) before promising any rich result.
- **Verify**: audit (types present, JSON validity, article dates/author) + Rich Results Test for one page per template.
- **Fix**: templates in `assets/templates/jsonld/`.
- **Keep fresh**: quarterly + whenever the gallery source changes in rules refresh.

## 3. AI

### ai-readable  ("pages AI can read")
- **Why**: most AI crawlers (GPTBot, ClaudeBot, PerplexityBot, CCBot and the ChatGPT/Claude user fetchers) do **not** execute JavaScript. Client-rendered pages look empty to them. Google renders JS but with delay.
- **Pass when**: main content, headings, prices/key facts and JSON-LD are in the server-delivered HTML (SSR/SSG/ISR/prerender); one `<h1>`; descriptive h2/h3 that work as questions or topics; key answers in plain text near the top of their section (not only in images, PDFs, tabs or accordions that require JS); internal links are real `<a href>`; no `nosnippet`/`max-snippet:0`/`noarchive` on pages that should be quoted (noarchive keeps content out of Copilot answers); images have alt text.
- **llms.txt**: optional. Google states Search ignores it; adoption by AI crawlers is low. Fine to keep a small, accurate one generated from the sitemap; never a substitute for readable HTML.
- **Verify**: audit (`client-rendered`, `h1-*`, `nosnippet`, `noarchive`, `thin-content`). App-only pages (dashboards, editors) should be `noindex` and out of the sitemap rather than made "readable". Spot-check with `curl -s URL | head` — if you can't read the content, neither can most AI crawlers.
- **Fix**: references/frameworks.md (SPA section), references/ai-visibility.md §Writing for citation.
- **Keep fresh**: on framework changes, new templates, new interactive components.

### ai-bots-allowed  ("AI bots allowed")
- **Why**: blocking an engine's search crawler or user-triggered fetcher removes you from its answers. Training crawlers are a separate, owner's-choice decision.
- **Pass when**: robots.txt allows every **search-engine**, **search** and **user** bot in `ai-bots.json` (+ override) and the social **preview** bots; training bots follow the owner's recorded choice (`config.ai_training_policy`); the CDN/WAF (Cloudflare AI bot policies — where a Training block can also hit mixed search+training crawlers — Bot Fight Mode, firewall rules) does not block or challenge those same bots; Search Console *Search generative AI* = Include (unless owner opted out).
- **Verify**: audit bot matrix; `audit.py --probe-bots` for edge hints; the CDN dashboard (agent asks the user, or reads it if a connector exists); `rules.py ai-bots` for new agents.
- **Fix**: templates `assets/templates/robots-*.txt`; references/ai-visibility.md §CDN.
- **Keep fresh**: monthly; immediately when rules refresh shows a vendor bot page changed or when moving to a new CDN plan.

## 4. Off-site

### directories  ("10 directories")
- **Why**: legitimate listings create citations/mentions that search and AI systems use to understand and trust an entity, and they send real visitors. Spammy directories do the opposite (Google link-spam policy).
- **Pass when**: ≥ 10 relevant listings live (configurable `directories_target`) chosen by site type and market, all with identical name, URL, short description, logo, category (and NAP for local); tracked in `.get-found/listings.json` with live URLs.
- **Verify**: `state.py listings`; open each live URL quarterly.
- **Fix**: references/directories.md (listing kit + workflow). Agent prepares copy and assets; the user creates accounts/submits (agents must not create accounts).
- **Keep fresh**: quarterly; on rebrand, new address/phone, new pricing, major launch.

### social-profiles
- **Why**: consistent official profiles linked both ways help engines connect the brand entity and make shares look right.
- **Pass when**: profiles that matter for the audience exist with the same name/logo/URL; the site links to them (footer); `sameAs` in homepage Organization JSON-LD lists them; link previews verified on LinkedIn Post Inspector, Facebook Sharing Debugger, and a draft post on X; Search Console *platform properties* (Instagram, TikTok, X, YouTube) added if the brand uses those platforms.
- **Verify**: audit (`sameas-missing`); config `social_profiles`.
- **Fix**: references/previews-social.md.
- **Keep fresh**: quarterly; when a new profile is created add it to config + sameAs.

## 5. Content

### keywords  ("1 real keyword")
- **Why**: each page should answer one real need people search for; two pages chasing the same query split signals.
- **Pass when**: every indexable page has one primary keyword in `.get-found/keywords.json` with evidence of real demand (Search Console impressions, Bing keyword data, Keyword Planner, autocomplete/People-also-ask), matching intent (informational/commercial/transactional/local), reflected naturally in title, h1, first paragraph and slug; `state.py keywords --check` clean (no duplicate primaries, no page without one).
- **Verify**: `state.py keywords --check`; monthly Search Console query data.
- **Fix**: references/content-engine.md §Keyword workflow.
- **Keep fresh**: monthly with the measurement report; new pages get a keyword before they ship.

### blog  ("1 blog post / week")
- **Why**: steady, genuinely useful posts cover more of what customers ask and build topical authority and citations. Frequency itself is **not** a ranking factor — usefulness is. A weekly cadence is a habit target, not a requirement; if quality would drop, slow down.
- **Pass when**: last post within `blog.cadence_days`; each post targets a backlog keyword not already owned by another page, has author byline + visible date + matching `datePublished/dateModified`, its own OG image, ≥ 2 internal links in and out, is in the sitemap/feed, and was submitted via sync.
- **Verify**: ledger `blog` (computed from published dates on ingest).
- **Fix**: post mode in SKILL.md + references/content-engine.md §Post workflow.
- **Keep fresh**: weekly; plus a quarterly refresh pass on old posts that lost traffic (update facts, then dateModified — never a date bump without real changes).

## 6. Measure & meta

### measurement
- **Pass when**: a monthly report exists in `.get-found/reports/` covering Search Console + Bing clicks, impressions, CTR, top queries/pages, AI citations (Bing AI Performance, Google generative AI report impressions), AI referral traffic (`utm_source=chatgpt.com`, referrers from AI assistants), keyword movements, and next actions.
- **Fix**: references/measurement.md.

### rules-fresh
- **Pass when**: `rules.py refresh` ran within 7 days; every CHANGED source reviewed; rule changes captured in `.get-found/rules-notes.md` / override files; feeds (`rules.py news`) skimmed for announcements.
- **Fix**: references/live-docs.md.
